# 계획 전략

> PRD → ROADMAP → Sprint 계획의 일관된 흐름.

## Phase 분할 원칙

1. **Phase 1 (MVP)**: PRD §3.1 핵심 기능만. 정상 흐름 (happy path) 위주.
2. **Phase 2 (확장)**: PRD §3.2 보조 기능. 사용자 피드백 반영.
3. **Phase 3 (최적화)**: 성능, 보안, 모니터링, 운영 안정성.

각 Phase의 종료 조건은 PRD §1.3 KPI에 정량적으로 묶여야 합니다.

## Sprint 크기

| 측정 | 권장값 | 이유 |
|---|---|---|
| 길이 | 2주 | 사용자 피드백 주기 |
| 작업 수 | 4~6 | 단일 개발자 기준 (병렬화 시 증가) |
| 작업당 평균 | 1~3일 | 큰 작업은 분할 권장 |

## 작업 정의

각 Sprint 작업은 다음 4요소를 가져야 합니다:

```markdown
### [작업명]
- **목표**: 무엇을 만드는가
- **인수 조건**: Given-When-Then 또는 체크리스트
- **추정**: X일
- **선행 조건**: 다른 작업 ID 또는 외부 의존성
```

## 리스크 관리

- 외부 통합 (결제, OAuth 등): 초반 Sprint에 배치
- 마이그레이션 (스키마 변경): Sprint 시작부에 배치
- UI는 백엔드 안정화 후 진행 (예외: 빠른 mock으로 병렬 가능)

## 회고 반영

각 Sprint 종료 시 `docs/sprint-retrospectives/sprintN.md` 작성:

- 잘 된 것 (Keep)
- 개선할 것 (Try)
- 멈출 것 (Stop)

다음 Sprint 계획에 Try 항목을 반영.
